**建议的最小实现边界**
- Swift 侧只保留一个新文件，例如 `crates/cua-macos-visual/swift/CuaCaptureBridge.swift`，imports 仅需 `Foundation`、`CoreGraphics`、`ScreenCaptureKit`，必要时 `CoreVideo` 只为 `kCVPixelFormatType_32BGRA`。不要 import `Metal`、`QuartzCore`、`CoreMedia`、`UniformTypeIdentifiers`、`AppKit`、`AVFoundation`、`IOSurface`。
- Swift ABI 建议用 opaque plan handle，而不是把 `SCWindow`/`SCContentFilter` 暴露给 Rust：
  - `cua_sc_plan_create(window_id, expected_pid, expected_layer, expected_bounds..., out facts, out_error) -> *mut Plan`
  - `cua_sc_plan_capture(plan, max_side, max_bytes, callback, user_data)`
  - `cua_sc_plan_release(plan)`
- `plan_create` 内：`SCShareableContent.get(excludingDesktopWindows: true, onScreenWindowsOnly: true, completionHandler:)` 找到 exact `windowID`，校验 `owningApplication.processID`、`windowLayer`、`frame`；创建 `SCContentFilter(desktopIndependentWindow:)`；读 `pointPixelScale`/`contentRect`；用 `SCStreamConfiguration()` 显式设 width/height、`pixelFormat = kCVPixelFormatType_32BGRA`、`showsCursor = false`。不要依赖默认 width 1920/height 1080，也不要依赖默认 pixelFormat。
- `plan_capture` 内：调用 `SCScreenshotManager.captureImage(contentFilter:configuration:completionHandler:)`；completion 内校验 image、尺寸、`max_side`/`max_bytes`，用 `CGContext` 以 `premultipliedLast` + device RGB 绘制为 RGBA，再把 `rgba ptr/len/width/height` 传给 C callback。缓冲区在 callback 返回前有效，Rust 复制后 Swift 释放。
- 不要添加 `Task`、`async`、`await`、`DispatchSemaphore` 或 5 秒伪超时。`SCScreenshotManager` 没有可信取消 API；如果 callback 永不返回，Rust operation 必须保持存活，不能释放 `user_data`。有界取消只能靠独立 Helper 进程边界，不能靠 Rust timeout。
- Rust 侧保留 `error.rs`、`geometry.rs`、`geometry_tests.rs`、`observe.rs`、`png.rs`、`tests/pure_visual.rs`、`swift_link.rs`；保留 `window.rs` 的 CGWindow facts（仍用 `core-foundation`，不引入 Swift）。重写 `capture.rs` 为调用新 bridge；删除 `screencapturekit` 依赖。
- `Cargo.toml` 只保留 `image`（png）和 macOS 下的 `core-foundation`；不再有 `screencapturekit`、`apple-cf`、`apple-metal`。`Cargo.lock` 中三者应消失。

**最终 Helper 的链接/rpath/部署验证**
- 建议直接 `swiftc` 编译单文件，不用 SwiftPM，避免 SwiftPM 的默认 platform 和 target 依赖：
  - `swiftc -parse-as-library -O -target arm64-apple-macos14.0 -sdk "$(xcrun --sdk macosx --show-sdk-path)" -module-name CuaCaptureBridge -c swift/CuaCaptureBridge.swift -o "$OUT/CuaCaptureBridge.o"`
  - `libtool -static -o "$OUT/libCuaCaptureBridge.a" "$OUT/CuaCaptureBridge.o"`
- `build.rs` 只对 macOS 生效，emit：
  - `cargo:rustc-link-search=native=$OUT`
  - `cargo:rustc-link-lib=static=CuaCaptureBridge`
  - `cargo:rustc-link-lib=framework=ScreenCaptureKit`
  - `cargo:rustc-link-lib=framework=Foundation`
  - `cargo:rustc-link-lib=framework=CoreGraphics`

- 部署目标建议直接定为 macOS 14.0：`SCScreenshotManager` 从 14.0 开始，`pointPixelScale`/`contentRect` 也是 14.0。最终 Helper 设置 `MACOSX_DEPLOYMENT_TARGET=14.0`，Swift 用 `-target arm64-apple-macos14.0`。不要重复 R8 的 `minos 11.0` 最终二进制配 `13.0` Swift object。若产品必须支持 13，则 Helper 编译到 13 并在 `if #available(macOS 14.0, *)` 内调用，13 上明确返回 unsupported。

**剩余假设与风险**
- `SCScreenshotManager.captureImage` 的 SDR 输出按 header 是 BGRA；假设不做 HDR，`CGContext` 转 RGBA 使用 premultiplied alpha。若未来要 HDR/RGhA，当前 8-bit RGBA 路径不成立。
- completion handler 只调用一次、在任意内部队列执行；Rust operation state 必须 `Send + Sync`，且不能在 callback 前释放。
- `captureImage` 没有取消 API；如果系统不回调，Rust 侧只能保持 operation 存活或依赖进程退出，不能伪造 timeout。
- 是否仍 autolink `libswift_Concurrency` 取决于 Swift/Foundation 的 autolink，源码不用 `Task` 不保证 `otool -L` 完全消失；若产品硬性要求最终二进制无 concurrency runtime，需要改用 ObjC/objc2 bridge，而不是 Swift。
- `SCShareableContent.get` 会触发屏幕录制权限/TCC；本轮只读，没有调用。未来只能在可信 Helper 许可接入后调用，公开入口继续 `HostNotApproved`。
- 当前只验证 arm64 macOS 26.6.2 / SDK 27.0；Intel、最低 macOS、Retina/多显示器和真实 TCC 仍未验收。
- 建议 controller 先写 spec，明确：Rust `CaptureOperation` 是 completion 状态唯一所有者；Swift `Plan` 只持有本次 SCK 对象；callback exactly-once；无 timeout/无重试/无窗口重选；默认禁用和 `HostNotApproved` 不变。
