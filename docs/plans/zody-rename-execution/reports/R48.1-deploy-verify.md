## 3. 方法、边界与计数口径

### 3.1 真实驱动路径

- 使用产品真实代码：`connectRemote` / `deployServer` / `performHandshake` / `acquireRemoteDeployLock` / local-only 资产安装（`@zody/server/remote/*`，经只读 harness 的 vitest 配置解析）。
- **darwin-arm64**：`LocalTargetBackend` 把每个远端命令以 `/bin/sh -c` 在隔离目标 HOME 中真实执行，`upload` 真实落盘到目标 HOME；`~/.zody/server/...` 由 shell 按 HOME 展开。部署决策的 `--version`、锁脚本、安装/替换、启动 server 均为真实进程。
- **linux-arm64**：`DockerTargetBackend` 用真实 `docker exec -i` / `docker cp` 操作本单元新建的 `r48e-target-*` 容器（隔离 HOME `/target-home-*`），容器在收尾删除；未触碰 `zclaudia-gateway-gateway-1` 或任何现网容器。
- 旧对端：R02 `zcode-server.cjs` 先复制进本单元 `legacy/server-dist/`，再以真实 Node 进程启动；未原地运行、未改旧包、未注入 require 预加载器。
- 边界：**不是 SSH**。R43 明确只允许隔离本地/合成目标；本单元验证的是产品 install-root 锁与部署/握手逻辑，在合成传输层上的真实执行，不代表真实 SSH 网络行为已实测。

### 3.2 计数口径

- `ackBytes`：产品 `performHandshake` 写入 server stdin 的字节数；拒绝格必须为 0（未发 ack）。
- `serverReady`：server stderr 出现 `stdio mode ready`（ack 后服务装配完成）。
- 业务写入：拒绝格用目标 HOME 文件清单 before/after 与 server stderr `client connected` 双重核对；成功格只建立连接，未发任何 RPC 业务请求。
- 清理：锁目录是否存在、`ps` 是否还有引用目标 HOME 的进程、容器内 `ps` 是否残留、容器是否删除。
- 每格证据 JSON 按该格采集项记录实际命令、退出码与结束方式（字段名如 `commands`/`exitRecords`/`processExit`，以各文件为准）；本报告 §5 只摘录结论。

## 5. 逐格证据

### D1 正常部署（darwin-arm64）

- 部署：7 次上传；运行实例 hello `{"type":"zody-hello","generation":2,"version":"0.1.0","platform":"darwin","arch":"arm64","pid":4624}`，ack 82 字节，`stdio mode ready=true`；stderr `client connected`、`stdio shutdown completed { exitCode: 0 }`，server `exitKind=stdin-eof`、exit 0（自然退出，非强杀）。
- 二次连接：`uploads=0`（部署决策命中同 SHA/版本后跳过安装），仍完成 hello 校验；锁目录 `{exists:false}`；残留进程 0。
- 安装落点 SHA：`~/.zody/server/zody-server.cjs` = `5f3405f3…`（与候选一致）。

### D2 离线未升级目标（darwin-arm64）

- 目标预置完整旧组合（旧 `zcode-server.cjs` + Node），旧实例 `--version` = `0.1.0`（仅作部署决策，不作为业务准入）。
- 传输层注入不可达：`ssh: connect to host isolated-target.invalid port 22: Network is unreachable`；连接失败，`ackBytes=0`，无 server 启动。
- 目标 HOME 清单 before/after：`{added:[],removed:[],changed:[]}`；锁目录不存在；残留进程 0。旧组合原样保留、可回退。

### D3 并发双 client（darwin-arm64）

- 两个独立 backend 同时 `connectRemote`，均成功：hello pid `4863`、`4899`，generation 均为 2、version 均 `0.1.0`。
- 上传：A=7，B=0（B 在锁内重查后发现已就绪，未重复覆盖）。
- 锁事件时间序：`acquired(token A) 1793857136972` → `release-sent(token A) 1793857138192` → `acquired(token B) 1793857139044`；第二租约在第一个 release 之后 852ms 才取得，无重叠。
- 最终锁目录不存在；残留进程 0；安装 bundle SHA `5f3405f3…`。

### D4 部署中断（darwin-arm64）

- 在 server bundle 上传点取消（`AbortController`），`deployServer` 以中断错误退出。
- 中断后：canonical `~/.zody/server/zody-server.cjs` **不存在**、server-bundle meta **不存在**；仅存在本 owner 的 `zody-server.cjs.new-<owner>` staging（SHA 与候选一致）与已完成的 node/node-runtime meta；恢复部署成功后该 staging 仍在（`postRecoveryInventory` 可核）。staging 残留是产品既有行为（`packages/server/src/remote/remoteAssetInstaller.ts:398-405`：取消路径不做二次 cleanup，留给后继 janitor），不构成业务入口。
- 用 `skipDeploy` 连接该目标：失败（canonical 不存在，Node 报 `MODULE_NOT_FOUND`），`ackBytes=0`、`serverReady=false`。
- 恢复：再次完整部署成功，hello `generation=2/version=0.1.0`；最终锁目录不存在、残留进程 0。

### D5 skipDeploy（darwin-arm64）

- 已正确部署目标 + `skipDeploy=true`：成功，`uploads=0`，无锁事件，hello `generation=2/version=0.1.0`。
- 旧 bundle 冒充“已部署”（新安装根放旧 `zcode-server.cjs` + Node）：`--version` 仍返回 `0.1.0`，但运行 hello 为 `{"type":"zcode-hello","version":"0.1.0",...}`；客户端在 ack 前拒绝：
  `Invalid hello: type: Invalid input: expected "zody-hello"; generation: Invalid input: expected 2`。
  `ackBytes=0`、`serverReady=false`、目标 HOME 清单 before/after 完全一致（零业务写入）。

### D6 旧部署者尝试（darwin-arm64）

- 非协作写入者：在 server bundle 的 `mv` 完成后、server 启动前，用**真实 R02 旧 bundle 字节**覆盖 canonical（旧部署者不遵守新锁）。实测覆盖前 canonical SHA = `5f3405f3…`（候选，上传记录中 `zody-server.cjs` 的 SHA 亦为候选），覆盖后 canonical = `06b7511c…`（旧）。
- 新客户端启动该实例后收到 `zcode-hello`，ack 前拒绝：`Invalid hello ... expected "zody-hello"`；`ackBytes=0`、`serverReady=false`；锁目录最终不存在、残留进程 0。
- 旧部署者写自己的旧安装根：旧实例 hello `zcode-hello`（pid 5401），新连接 hello `zody-hello generation=2`（pid 5471），两者根目录/进程独立；关闭后目标无残留进程。
- **blocked 子项**：真实 R02 desktop（Electron）部署器启动未验证，见 §8。

### D7 回退（darwin-arm64）

- 注入失败：server bundle 安装成功（canonical 候选 SHA、server-bundle meta 已写）后，glm 上传失败；连接未进入启动阶段，`ackBytes=0`。
