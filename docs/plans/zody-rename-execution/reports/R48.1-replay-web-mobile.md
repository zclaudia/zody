## 10. 未验证、残留与需主控裁决

### 10.1 明确未验证（不冒充通过）

- Android 设备层 A-MN-01…A-MO-01（D-01 blocked）。
- 完整 E2E-P `mobile-host-identity-isolation.test.ts`（D-02 blocked）：Electron 真实 Host attachment、“无第二 Host/Agent”的应用层证据缺失；协议层只证明单 session/单 backend。
- Win-x64 / linux-arm64 的 L4 Web 格不在本单元派发范围（本单元按派发只要求 darwin-arm64）。
- 手机协议层使用源码形态产品组件（commit 8072db7），未使用打包 desktop dist（R48.0 desktop 构建 exit 1）；若验收要求“安装包形态对端”，需先产出可验收 desktop 候选后补跑。

### 10.2 环境事实（非产品缺陷）

- Docker `docker restart` 对 `-p 127.0.0.1::3200` 的随机端口会重新分配映射，导致按旧端口做健康检查超时；固定端口后 7/7。已在 §5.2 记录，避免被误判为“重启恢复失败”。
- 旧页 `?remote=` 分支不请求 server-info 是 R02 旧产物既有逻辑，不是新代码回退。

### 10.3 疑似既有 UX 缺陷（只回报，不修）

- 路径：`packages/web/src/main.tsx`（连接后直接渲染）+ `packages/client/src/websocket.ts:91-100`（`open` 即 resolve）+ `packages/server/src/http.ts:441-452`（upgrade 后立即 `close 4004`）。
- 复现：new web 访问 `/?remote=<不存在的 id>` against new server。
- 现象：WS 101 后立即被 4004 关闭，`connectViaWebSocket` 已在 `open` 时 resolve，页面设置标题后渲染出**空白正文**，不显示“远程连接不存在/已失效”错误页。
- 证据：`logs/smoke-remoteid.json`（`webSocketCreated` → `101` → `webSocketClosed`，`bodyText` 为空，无 console error）、`evidence/web-matrix.json` W-02 `remotePage`。
- 判断：与改名代际无关，属既有 remoteId 失败 UX；建议主控派回 L4 Web owner 评估（本单元按规则不修）。
