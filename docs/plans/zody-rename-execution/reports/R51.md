## 1. 结论摘要

1. **双命名空间落地**：`window.zody` 与只读 `window.zcode` 在 alias 与 Gen UI 页面运行时都指向**同一个 API 对象**（`alias.ts:45-56`、`genUi.ts:224-227`）；不是两个 runtime、两条 ready 路径或两套保存队列。
2. **单次副作用**：Gen UI 发送端四类操作统一走 `pickGenUiMethodName`（`genUi.ts:33-44`），一次操作只发一个方法名；宿主侧四个方法双名注册到**同一 handler 闭包**（`page.ts:186-249`），保存队列、follow-up 绑定、tweak registry 仍只有一份。
3. **通知双名来自一次投影**：`zcode:globals`（保持基线无 payload）与 `zody:globals`（`detail.globals`，与 `openai:set_globals` 同源）来自同一次 `onChange`；`zcode:set_globals`/`zody:set_globals` 共用同一 detail 对象；`zcode:error`/`zody:error` 经同一 `dispatchDualEvent` helper 派发（`genUi.ts:46-54`、`alias.ts:28-35`）。
4. **出站双表示**：`hostContext` 的 `zody/genUiState`↔`zcode/genUiState`、`zody/genUiTweaks`↔`zcode/genUiTweaks` 由 `projectGenUiContextEntries` 一次投影，两键同引用；能力宣告改为 `buildGenUiExperimentalCapability()`（恰两键）。
5. **origin/partition 未动**：`zcode-sandbox://`、`persist:plugin-sandbox-v2-*`、`__zcode__/*` 路径段与 `__ZCODE_GEN_UI_*__` 标记、`zcode-gen-ui-initial-state` DOM id 均未改写；`genUiVendor.ts`/`protocol.ts`/`session.ts`/`services gen-ui service.ts` 未改（origin 例外，R56 退役清单复核）。
6. **验证**：目录级定向测试 49 + 11 passed；`pnpm typecheck` exit 0；E2E 可编译 `tsc -p tsconfig.e2e.json --noEmit` exit 0；fixture check exit 0；`pnpm lint` exit 0（303 warnings，与 R50 基线同级）；`pnpm architecture:check --changed` 0 violations / 0 new；12 个改动文件 `oxfmt --check` 通过。E2E **未执行，归 R56**。

## 3. 规则与状态所有者

```text
页面（不可信）                   唯一 owner（既有）                         派发
window.zody === window.zcode ─┐
  Gen UI 运行时 (genUi.ts)    │  page.ts: onState → saves 队列 → IGenUiService.setState
  四态单选一个方法名 ─────────┴─→ follow-up → 既有 session input 绑定
  一次操作一次 request           presentation → snapshot.escapeSequence
  未宣告 → 不发送、不重发        tweak → 既有 createGenUiTweakRegistry
页内事件：一次投影 → 旧名 + 新名各派发一次（legacy `zcode:globals` 无 payload，canonical `zody:globals` 带同源 detail）
hostContext：同一快照 → canonical 键 + legacy 键（同引用）
```

- **不新增状态**：`widgetState`/`tweakAnnotation` 是既有 hostContext 快照的投影字段，不是第二个 owner；保存队列仍是 `saves`，follow-up 仍是 `followUp()`。
- **不新增写入路径**：双名 handler 只注册同一函数引用；旧名没有独立 handler、队列或授权。
- **失败语义**：宿主未宣告任何 Gen UI 能力时不发送；页面侧 state/follow-up/tweak 以明确错误 reject（不伪装成功、不改名重发）。presentation 保持既有静默 catch（纯展示事件）。

### 4.1 新增用例逐项

**aliasRuntime（9）**

1. `zcode:globals` / `zody:globals` 字节值与互异。
2. 一次宿主变更 → `onChange` 恰一次（alias 双名派发的投影源）。
3. widgetState 初值 canonical 优先、缺省回退 legacy。
4. canonical `null` 快照不被旧值回填（`hasOwn` 语义）。
5. `zody`/`zcode` 访问 + 显式 `ready()` 只握手一次。
6. 订阅者每次变更恰一次、注销后不再回调。
7. 两类通知 handler 只注册一次，单次资源更新对每个 listener 只派发一次。
8. `setWidgetState` 每次调用恰一条 `ui/set-widget-state`、恰一次通知。
9. `openExternal` 每次调用恰一次 `app.openLink`（外链副作用不放大）。

**page（8）**

1. 能力宣告恰 `zody/gen-ui`、`zcode/gen-ui` 两键。
2. 四对方法名都已注册且 handler 引用恒等（`toBe`）。
3. canonical 与 legacy 各发一次 → `setState` 各一次（同队列，不放大）。
4. legacy follow-up 恰一次 `sendFollowUp`，target/source 正确。
5. legacy presentation 每次请求 `escapeSequence + 1`（不重复投影）。
6. hostContext 双键 `toBe` 同引用、值等于最新快照、tweak 非空。
7. 外链请求：消费恰一次手势 → `openExternal` 恰一次、URL 原样。
8. 无手势：请求 reject（`user gesture`），`openExternal` 零调用。

## 6. 偏差、设计与残留

1. **spec 增补保持在授权的一行内（返修后）**：预案 §2.1 #11 / file-assignments gate 只授权"§1.1 增一行 + §6 改状态"。指令 ② 要求 `zcode:error` 双名派发，为满足 spec 先行又不越过 gate，返修把该说明折进新增的 `zcode:globals` 行 owner 单元格（同一行内），不再有表外独立段落。
2. **`window.zody` 同时加入 `genUi.ts`**：预案 #1/#2 只点名 alias.ts。为避免"普通插件页有 zody、Gen UI 页没有"的命名空间缺口，Gen UI 页面运行时同样把 `window.zody` 指向既有 `api`（同一冻结对象）。不新增状态或请求路径。
3. **发送端在能力缺失时 reject 而非静默**：`setWidgetState`/`sendFollowUpMessage`/tweak 在宿主未宣告能力时不发送，并以明确错误 reject；避免页面误以为保存/发送成功。presentation 维持既有静默 catch（纯展示）。
4. **tweak 双键回退接受 `null`**：`page.ts` 的 hostContext 投影在无 tweak 时写入 `null`（`projectGenUiContextEntries` 要求双键同值），`genUi.ts` 将 `null` 视为"无 annotation"，不触发 schema 解析错误；state 的 `null` 语义保持原样（合法空状态）。
5. **legacy `zcode:globals` 的 wire 形状保持基线（返修采纳 P3-4）**：初版曾让 legacy 事件也携带 `{ globals }` detail；返修已回退为**无 payload**（与基线逐字节一致），只有新增的 canonical `zody:globals` 携带 `detail.globals`，且与 `openai:set_globals` 共用同一对象。spec 行与 CONTRACT.md 已同步写明。
6. **E2E 的手势/事件族/外链返修（采纳 P2-1/P2-2/P2-3）**：
   - follow-up 与外链都依赖 guest 真实手势（`guestPolicy.ts:164-172` 的 `input-event` 打点、`registry.ts:214-220` TTL 内一次消费），页面不能自造；用例改为从 main process 找到持有该 marker 的 guest webContents，`focus()` 后注入 `mouseDown`/`mouseUp`，第一次手势发 follow-up、第二次手势开外链。
   - Gen UI 页只会收到 `zcode:set_globals`/`zody:set_globals`（`genUi.ts` 派发）；`zcode:globals`/`zody:globals` 由 alias 运行时（插件页）派发。用例从四事件计数改为 `set_globals` 两事件，并按 variant 断言：旧页 legacy>0/canonical=0，新页反之，迁移页两者相等且>0。
   - 外链用 `browser.electron.mock("shell", "openExternal")`，每个 variant 断言恰好一次且 URL 精确匹配；单测另补 page 有手势/无手势两例与 aliasRuntime `openLink` 一例。
7. **E2E 未执行，归 R56**，且有两个前置风险需在 R56 确认：
   - fixture 的 `::visualize` 路径依赖运行时 token `{{genUiOutputRoot}}`，只有 **spec 级 replay server**（`fixtureVariables` 携带该 token）能展开；用例采用 `conversation-session-markdown-table-layout.test.ts:90-92` 同款"spec 内自起 replay server + 覆盖 provider 环境变量"模式。若 app 的 agent session 仍绑定 wdio 全局 replay server（只展开 `e2eRuntimeRoot`），路径会保留字面量而失败。
   - 页面 `sendFollowUpMessage` 会开启下一次真实 turn，该请求没有对应 fixture；当前用例只断言 follow-up 用户消息与落盘状态，不要求该 turn 成功。R56 执行时可补一条兜底 fixture 或接受错误态终态。
   - 手势注入依赖 `webContents.sendInputEvent` 能触发 guest 的 `input-event`；R56 需以真实 Electron 确认（本机未执行）。
8. **E2E 中 MCP Apps / CLI 两段为 `it.skip`**：分别等待 R52/R53 报告里的边界数据（资源 `_meta` 冲突样例、canonical/legacy tool result fixture）。R51 是唯一写者，R56 执行前由主控汇总启用。
9. **legacy 方法名的发送端选择未在 E2E 覆盖**：宿主 page.ts 双宣告后发送端总选 canonical，真实链路不会走 legacy；legacy 接收由 page.test.ts 的双名 handler 用例覆盖，四态选择由 shared `contract.test.ts` 覆盖。若 R56 需要真实 legacy 链路，需要"仅宣告 legacy 的旧宿主"场景，R51 不提供第二套宿主。

12. **origin 例外判定沿用预案 §5.2**：`__zcode__/*`、`__ZCODE_GEN_UI_*__`、`zcode-gen-ui-initial-state` 未改；建议主控在 manifest 补录 explicit-retention（预案 §5.2 原文），R56 逐项复核。
