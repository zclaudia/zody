# 远端部署与运行实例准入

连接前沿用现有 deployment/资源锁和安装器；部署中的 `--version`、bundle 静态标记和 SHA 是判断是否需要刷新文件的线索，不能作为运行实例准入。每次实际启动，包括 skipDeploy，在 RemoteServer hello 严格 schema/代际验证后、发送 ack 前，将运行 hello.version 与客户端当前产品版本精确比较；不匹配立即拒绝，不发 ack、不注册本地 RPC，连接 owner 关闭 backend。遵守 R41 的新 server 在 ack 前不初始化业务服务；不受控旧 server 可能在 hello 之前已初始化，不声称其零初始化。generation 与产品版本分别验证，不能互相替代。

部署默认使用远端 install-root 锁，获取后重新检查现状及固定 manifest，失败与释放均保留因果；调用方串行模式依赖实际调用方的串行边界，不能假定旧进程遵守同一锁。上线必须盘点目标、暂停所有旧自动部署者、逐个部署并核实实际运行实例，失败保留或恢复完整旧组合，不得混布开放连接。锁持有者释放时必须终止并回收自身 heartbeat 及其 sleep 子进程，不得遗留管道或后台进程；不影响其他 owner。取消、离线、失败及并发重试均不可把未完成安装或静态标记当作已验证业务入口。

验收用隔离本地伪目标及合成数据验证同版本/异版本、skipDeploy、锁内重查、旧标记、失败/取消/重连、环境注入与资源清理；不得在开发验证中部署真实远端。
